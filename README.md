# 楽天ROOM投稿アシスタント

楽天ROOMへ投稿する商品の検索、紹介文作成用プロンプト、投稿候補、投稿履歴をまとめて管理する静的Webアプリです。

HTML、CSS、JavaScriptだけで動きます。サーバーやログイン機能は使いません。

## 大事な方針

このアプリは、楽天ROOMへの自動投稿を行いません。

紹介文やハッシュタグを作る作業を助け、最後は利用者が内容を確認して手動で投稿するための補助アプリです。

## 主な機能

- 楽天市場の商品検索
- 商品画像、商品名、価格、ショップ名、レビュー情報の表示
- ChatGPTへ渡す紹介文作成プロンプトの生成
- 紹介文とハッシュタグの編集、コピー
- 投稿候補の保存
- 投稿済み商品の記録
- 重複商品の確認
- 投稿履歴検索
- 投稿履歴CSV出力
- JSONバックアップ、復元
- スマートフォン対応
- お気に入り管理
- 投稿予定日の管理
- 月別投稿予定画面
- ジャンル別投稿数の表示
- ChatGPTを開いてプロンプトを貼り付けやすくする機能
- 楽天ランキング表示

### Ver.2-1で追加した機能

- 楽天市場の主要カテゴリーを複数選択したランキング取得
- 1位のみ、または1〜3位の取得順位選択
- カテゴリー別のランキング表示
- ランキング商品へのカテゴリーID、カテゴリー名、順位、取得日時の付加

Ver.2-1では、重複商品の自動除外、投稿キュー、ROOM画面の自動操作、投稿完了の自動クリックは行いません。

## 使い方

1. `index.html` をブラウザで開きます。
2. 「設定」で楽天アプリIDと楽天アクセスキーを入力します。
3. 「商品検索」でキーワードを入力して検索します。
4. 商品の「詳細・紹介文」を開きます。
5. 「紹介文プロンプトを作る」を押します。
6. プロンプトをコピーしてChatGPTへ貼り付けます。
7. 作成した紹介文とハッシュタグをアプリに貼り付けます。
8. 「投稿候補に保存」を押します。
9. 楽天ROOMには自分で内容を確認して手動投稿します。
10. 投稿後に「投稿済みにする」を押して履歴に残します。

楽天アプリIDまたは楽天アクセスキーを入れていない場合は、サンプル商品で動作確認できます。

## 楽天アプリIDについて

楽天APIの利用には、楽天ウェブサービスで発行されるApplication IDとAccess Keyの両方が必要です。

このアプリでは、両方をアプリの設定画面から入力します。

GitHubのHTMLやJavaScriptへApplication IDやAccess Keyを直接書かないでください。

この静的Webアプリでは、入力したApplication IDとAccess Keyをブラウザの `localStorage` に保存します。

GitHub Pagesなどの公開ページで使う場合、ブラウザの開発者ツールから保存内容を確認できる可能性があります。

より安全に運用する場合は、Netlify Functions、Cloudflare Workers、Vercel Functionsなどのサーバー側処理を利用し、Application IDとAccess Keyをサーバー側の環境変数で管理してください。

## 楽天ウェブサービスの利用について

このアプリは、楽天ウェブサービスの楽天市場商品検索APIを利用します。

また、ランキング画面では楽天ランキングAPIを利用します。

楽天ウェブサービス公式ルールに基づき、アプリ画面の最下部に公式クレジットバッジを表示しています。

このクレジット表示は削除しないでください。

クレジット表示を変更する場合は、必ず楽天公式のクレジット表示ガイドを確認してください。

公式確認先: https://webservice.rakuten.co.jp/guide/credit

楽天アプリIDと楽天アクセスキーは、GitHubのソースコードへ直接書かないでください。

アプリIDとアクセスキーは、利用者自身がアプリの設定画面から入力する仕様です。

このページには、検索エンジン向けに `noindex` 設定を入れています。ただし、検索エンジン側の反映には時間がかかる場合があります。

## 保存データ

データは同じブラウザ内の `localStorage` に保存されます。

保存対象は次のとおりです。

- 投稿候補
- 投稿履歴
- 紹介文
- ハッシュタグ
- アプリ設定

別の端末やブラウザには自動同期されません。

必要に応じて「設定」画面からJSONバックアップを保存してください。

## 注意

- 楽天会員IDやパスワードは保存しません。
- 楽天ROOMへのログイン情報は取得しません。
- ROOMへの自動投稿、自動いいね、自動フォローは実装していません。
- 商品価格、在庫、セール期間は投稿前に楽天市場で確認してください。
- 実際に使っていない商品を「使いました」と書かないでください。
- 医療、健康、美容などの効果を断定しないでください。
- 商品提供や専用クーポンなどがある場合は、PR表記の要否を利用者自身で確認してください。

## GitHub Pagesで公開する方法

1. このフォルダのファイルをGitHubリポジトリに置きます。
   - `index.html`
   - `style.css`
   - `script.js`
   - `README.md`
2. GitHubのリポジトリで `Settings` を開きます。
3. `Pages` を開きます。
4. `Deploy from a branch` を選びます。
5. 公開するブランチとフォルダを選びます。
6. 数分後に表示されるURLからアプリを開けます。

## Ver.2-4の投稿キュー

投稿候補一覧は、採用商品を1件ずつ処理する投稿キューとして利用できます。

- 「Codex投稿開始」で、商品情報とROOM投稿手順を含む指示文を作成し、クリップボードへコピーします。
- 指示文には、商品番号からROOM URLを推測せず、楽天商品ページのJavaScript実行後DOMから `aria-label="ROOMに投稿"` の実hrefを取得する手順を含めています。
- Codex処理後は「確認待ちにする」で状態を更新できます。
- ROOMの「完了」は利用者が確認して手動で押してください。アプリはROOMの完了、自動いいね、フォロー、コメントを実行しません。
- 投稿後に「投稿済みにする」を押すと、既存の投稿履歴へ記録されます。
- クリップボードが使えない場合は、カード内のCodex投稿指示文を開いて手動コピーできます。

## Ver.2-6の連続処理

- 投稿キュー上部の「連続処理開始」で、投稿待ち商品の先頭1件だけをCodex処理中にします。
- 紹介文とハッシュタグはROOMを開く前に `#codex-result-input` へ保存し、itemCode完全一致を確認します。
- Google Chromeの同じプロフィールで、利用者が楽天ROOM固定タブを1枚開いておく必要があります。ROOM用の新規タブは作成しません。
- Codex処理中または確認待ちの商品がある間は、別商品の処理を開始できません。
- ROOMの商品一致、紹介文入力、ハッシュタグ入力を確認したら、ROOMの「完了」は利用者が手動で押します。
- 投稿済みにした後、「次の商品を処理」で次の投稿待ち商品を手動開始します。
