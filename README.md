# 楽天ROOM投稿アシスタント

楽天ROOMへ投稿する商品の検索、紹介文作成用プロンプト、投稿候補、投稿履歴をまとめて管理する静的Webアプリです。

HTML、CSS、JavaScriptだけで動きます。サーバーやログイン機能は使いません。

## 大事な方針

このアプリは、楽天ROOMへの自動投稿を行いません。

紹介文やハッシュタグを作る作業を助け、最後は利用者が内容を確認して手動で投稿するための補助アプリです。

## 主な機能

- 楽天市場の商品検索
- 商品画像、商品名、価格、ショップ名、レビュー情報の表示
- ROOM紹介文・ハッシュタグ作成用プロンプトの生成
- 商品データに明記されたセール情報（価格、割引、クーポン、期間、ポイント等）の紹介文反映
- 対象者・悩みを冒頭に置き、特徴、利用場面、選ぶ理由、必要なセール情報へ続ける紹介文プロンプト
- 商品ごとの対象者、悩み、メリット、利用シーン、使用状態、今チェックする理由を中間情報として整理
- 商品カテゴリー、用途、悩み、利用シーン、セール情報に連動したハッシュタグ生成
- 商品信頼性チェック（通常投稿候補・要確認・注意喚起候補・投稿対象外）
- 信頼性チェック理由の表示と注意喚起文章用プロンプト
- 注意喚起候補への「🔍 買う前に確認したい商品」コレクション推奨と手動選択
- 紹介文とハッシュタグの編集、コピー
- 投稿候補の保存
- 「Threads投稿」によるThreads限定候補の保存（ROOM投稿候補とは分離）
- 候補管理を「投稿候補（ROOM自動運用）」と「Threads投稿（Threads限定アフィリエイト投稿）」のタブで分離
- Threads成果型 Ver.1（誰向け・お得・期限／今見る理由）の文章作成
- 投稿済み商品の記録
- 重複商品の確認
- 投稿履歴検索
- 投稿履歴CSV出力
- JSONバックアップ、復元
- スマートフォン対応
- お気に入り管理
- 投稿予定日の管理
- 月別投稿予定画面
- ジャンル別投稿数の表示
- ChatGPT用プロンプトをコピーする補助機能
- ROOM URL登録後、CodexがX・Threads文章を作成してアプリへ直接反映する機能
- 楽天ランキング表示

### Ver.2-1で追加した機能

- 楽天市場の主要カテゴリーを複数選択したランキング取得
- 1位のみ、または1〜3位の取得順位選択
- カテゴリー別のランキング表示
- ランキング商品へのカテゴリーID、カテゴリー名、順位、取得日時の付加

Ver.2-1では、重複商品の自動除外、投稿キュー、ROOM画面の自動操作、投稿完了の自動クリックは行いません。

## 使い方

1. `index.html` をブラウザで開きます。
2. 「設定」で楽天アプリIDと楽天アクセスキーを入力します。
3. 「商品検索」でキーワードを入力して検索します。
4. 商品の「詳細・紹介文」を開きます。
5. 「紹介文プロンプトを作る」を押し、CodexでROOM紹介文とハッシュタグを作成してアプリへ反映します。CodexがChromeを操作できる環境を正式経路とし、ChatGPT Workは利用可能な場合の選択肢であって必須条件ではありません。
6. 内容を確認して「投稿候補に保存」を押します。
   - ROOMへ投稿する商品は、このボタンを使います。
   - ROOMへ投稿せずThreadsだけで紹介する商品は「Threads投稿」を押します。候補管理画面の「Threads投稿」タブへ保存され、ROOM投稿待ちにならず、ROOM個別URLも要求しません。
7. 楽天ROOMで紹介文とハッシュタグを確認し、手動で投稿します。
8. SNSにも投稿する商品だけ、ROOMの投稿完了後に表示された確定ROOM個別URLを候補カードへ入力し、「登録完了」を押します。この操作でROOM商品を投稿済みにし、投稿履歴・投稿日・確定URLを同時に保存します。ROOMだけに投稿する商品はURLを登録せず、SNS文章も作成しません。
9. SNS展開対象で「登録完了」した場合、Codexは停止せず、既存のChrome操作でX・Threads本文を作成してアプリの結果欄へ直接入力し、「X・Threadsに反映」を押します。「CodexでX・Threads作成」ボタンは補助・再実行用です。ChatGPT Webへの手動貼り付けは通常運用では行いません。
10. Xの140文字、確定ROOM URL、`#PR`、ThreadsのURL完全一致1回などを検証し、人間が内容確認します。各SNSへの実投稿後だけ「投稿済みにする」を押して`postedAt`を保存します。

Threads限定候補は「Threads限定投稿」欄で管理します。基本はThreads成果型 Ver.1を使い、確認済みの商品情報だけで文章を作成します。設定画面に楽天アフィリエイトIDを入力した場合は、楽天APIが返すaffiliateUrlを保存して本文または返信用文章へ利用できます。未設定・未取得時は商品URLやROOM URLを代用せず、URLを生成しません。外部Threadsへの投稿は自動化せず、内容確認後に利用者が投稿します。

Threads成果型 Ver.1では、誰向けを商品カテゴリー名だけで済ませず、商品情報から合理的に導ける具体的な利用場面・小さな困りごとへ絞ります。本文＋返信URL方式では、親投稿にaffiliateUrlを入れず、「対象は返信に👇」などの導線を置き、返信へ確認済みaffiliateUrlと`#PR`を記載します。

候補管理画面では、「投稿候補」タブがROOM投稿専用、「Threads投稿」タブがThreads限定アフィリエイト投稿専用です。タブを切り替えても保存データや投稿状態は変更されません。

Threads投稿タブの「お得商品検索」では、50%以上・50%・40%・30%・20%・10%の検索候補を楽天商品検索APIから探せます。検索ヒットは割引確認済みを意味しないため、確認した割引率・期限を入力して保存します。標準方式はThreads本文と`THREADS_REPLY`の分離で、親投稿にURLを入れず、確認済みの楽天アフィリエイトURLを返信用文章へ反映します。RaCouponは公式ページを開いて人間が確認する補助として扱い、直接スクレイピングは行いません。

楽天アプリIDまたは楽天アクセスキーを入れていない場合は、サンプル商品で動作確認できます。

## 楽天アプリIDについて

楽天APIの利用には、楽天ウェブサービスで発行されるApplication IDとAccess Keyの両方が必要です。

このアプリでは、両方をアプリの設定画面から入力します。

GitHubのHTMLやJavaScriptへApplication IDやAccess Keyを直接書かないでください。

この静的Webアプリでは、入力したApplication IDとAccess Keyをブラウザの `localStorage` に保存します。

GitHub Pagesなどの公開ページで使う場合、ブラウザの開発者ツールから保存内容を確認できる可能性があります。

より安全に運用する場合は、Netlify Functions、Cloudflare Workers、Vercel Functionsなどのサーバー側処理を利用し、Application IDとAccess Keyをサーバー側の環境変数で管理してください。

## 楽天ウェブサービスの利用について

このアプリは、楽天ウェブサービスの楽天市場商品検索APIを利用します。

また、ランキング画面では楽天ランキングAPIを利用します。

楽天ウェブサービス公式ルールに基づき、アプリ画面の最下部に公式クレジットバッジを表示しています。

このクレジット表示は削除しないでください。

クレジット表示を変更する場合は、必ず楽天公式のクレジット表示ガイドを確認してください。

公式確認先: https://webservice.rakuten.co.jp/guide/credit

楽天アプリIDと楽天アクセスキーは、GitHubのソースコードへ直接書かないでください。

アプリIDとアクセスキーは、利用者自身がアプリの設定画面から入力する仕様です。

このページには、検索エンジン向けに `noindex` 設定を入れています。ただし、検索エンジン側の反映には時間がかかる場合があります。

## 保存データ

データは同じブラウザ内の `localStorage` に保存されます。

保存対象は次のとおりです。

- 投稿候補
- 投稿履歴
- 紹介文
- ハッシュタグ
- アプリ設定

別の端末やブラウザには自動同期されません。

必要に応じて「設定」画面からJSONバックアップを保存してください。

## 注意

- 楽天会員IDやパスワードは保存しません。
- 楽天ROOMへのログイン情報は取得しません。
- ROOMへの自動投稿、自動いいね、自動フォローは実装していません。
- 商品価格、在庫、セール期間は投稿前に楽天市場で確認してください。
- セール情報は商品データに明記された項目だけがプロンプトへ渡されます。記載がない割引率や通常価格を推測しません。
- 紹介文プロンプトは、商品情報から合理的に判断できる対象者や小さな悩みを冒頭へ置きます。状態不明の商品は使用体験を書かない指示になります。
- 商品信頼性チェックは自動断定ではありません。レビュー評価だけで安全判定せず、メーカー、型番、スペック、価格、保証、説明の整合性を確認し、判断できない場合は「要確認」とします。
- 注意喚起候補は、購入前に確認したい商品を整理するコレクション候補です。偽物・危険商品の断定やROOM側への自動登録は行いません。最終的なコレクション選択と投稿は利用者が確認して行います。
- 実際に使っていない商品を「使いました」と書かないでください。
- 医療、健康、美容などの効果を断定しないでください。
- 商品提供や専用クーポンなどがある場合は、PR表記の要否を利用者自身で確認してください。

## GitHub Pagesで公開する方法

1. このフォルダのファイルをGitHubリポジトリに置きます。
   - `index.html`
   - `style.css`
   - `script.js`
   - `README.md`
2. GitHubのリポジトリで `Settings` を開きます。
3. `Pages` を開きます。
4. `Deploy from a branch` を選びます。
5. 公開するブランチとフォルダを選びます。
6. 数分後に表示されるURLからアプリを開けます。

## Ver.2-4の投稿キュー

投稿候補一覧は、採用商品を1件ずつ処理する投稿キューとして利用できます。

- 「Codex投稿開始」で、商品情報とROOM投稿手順を含む指示文を作成し、クリップボードへコピーします。
- 指示文には、商品番号からROOM URLを推測せず、楽天商品ページのJavaScript実行後DOMから `aria-label="ROOMに投稿"` の実hrefを取得する手順を含めています。
- Codex処理後は「確認待ちにする」で状態を更新できます。
- ROOMの「完了」は利用者が確認して手動で押してください。アプリはROOMの完了、自動いいね、フォロー、コメントを実行しません。
- 投稿後に「投稿済みにする」を押すと、既存の投稿履歴へ記録されます。
- クリップボードが使えない場合は、カード内のCodex投稿指示文を開いて手動コピーできます。

## Ver.2-6の連続処理

- 投稿キュー上部の「連続処理開始」で、投稿待ち商品の先頭1件だけをCodex処理中にします。
- 紹介文とハッシュタグはROOMを開く前に `#codex-result-input` へ保存し、itemCode完全一致を確認します。
- Google Chromeの同じプロフィールで、利用者が楽天ROOM固定タブを1枚開いておく必要があります。ROOM用の新規タブは作成しません。
- Codex処理中または確認待ちの商品がある間は、別商品の処理を開始できません。
- ROOMの商品一致、紹介文入力、ハッシュタグ入力を確認したら、ROOMの「完了」は利用者が手動で押します。
- 投稿済みにした後、「次の商品を処理」で次の投稿待ち商品を手動開始します。

ROOM投稿後のSNS運用では、保存済みのROOM紹介文・ハッシュタグは再生成せず、確定したROOM個別URLを使ってX・Threadsだけを生成します。XはROOM URL・`#PR`・改行を含む全文140文字以内、Threadsには140文字制限を設けません。

通常運用では、SNSにも投稿する商品のROOM個別URLを「登録完了」した後、Codexが停止せずにX・Threads文章の作成・アプリ反映まで続けます。`===X_POST===` / `===THREADS_POST===`形式の結果をアプリへ直接反映し、検証後に人間の最終確認で停止します。ROOMだけに投稿する商品ではURL登録もSNS文章作成も行いません。アプリは外部AI APIへ接続しません。既存の「CodexでX・Threads作成」ボタンとChatGPT用プロンプトコピー機能は、補助・再実行・個別確認用です。
