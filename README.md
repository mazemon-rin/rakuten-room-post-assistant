# 楽天ROOM投稿アシスタント

公開版：Ver.2-7.1.4 — https://mazemon-rin.github.io/rakuten-room-post-assistant/

楽天ROOMへ投稿する商品の検索、紹介文作成用プロンプト、投稿候補、投稿履歴をまとめて管理する静的Webアプリです。

HTML、CSS、JavaScriptだけで動きます。サーバーやログイン機能は使いません。

## 大事な方針

ROOM投稿候補の通常経路は、指定件数を1件ずつ処理する連続投稿です。外部公開は現在の依頼で明示的に許可された場合だけ行い、商品照合と投稿履歴の重複確認を維持します。投稿結果が不明な場合は再投稿せず停止します。確認モードは任意で、入力済みのROOM編集画面で「完了」の前に停止します。オリジナル写真投稿は写真追加と「完了」を行わず、編集画面を維持して利用者へ引き渡します。

紹介文やハッシュタグは確認できる商品情報だけで作成し、未使用・使用状態不明の商品に購入・使用・飲食の体験談を生成しません。

## 主な機能

- 楽天市場の商品検索
- 商品画像、商品名、価格、ショップ名、レビュー情報の表示
- ROOM紹介文・ハッシュタグ作成用プロンプトの生成
- 商品データに明記されたセール情報（価格、割引、クーポン、期間、ポイント等）の紹介文反映
- 対象者・悩みを冒頭に置き、特徴、利用場面、選ぶ理由、必要なセール情報へ続ける紹介文プロンプト
- 商品ごとの対象者、悩み、メリット、利用シーン、使用状態、今チェックする理由を中間情報として整理
- 商品カテゴリー、用途、悩み、利用シーン、セール情報に連動したハッシュタグ生成
- 商品信頼性チェック（通常投稿候補・要確認・注意喚起候補・投稿対象外）
- 信頼性チェック理由の表示と注意喚起文章用プロンプト
- 注意喚起候補への「🔍 買う前に確認したい商品」コレクション推奨と手動選択
- 紹介文とハッシュタグの編集、コピー
- 投稿候補の保存
- 「Threads投稿」によるThreads限定候補の保存（ROOM投稿候補とは分離）
- 候補管理を「投稿候補（ROOM自動運用）」と「Threads投稿（Threads限定アフィリエイト投稿）」のタブで分離
- Threads成果型 Ver.1（誰向け・お得・期限／今見る理由）の文章作成
- 投稿済み商品の記録
- 重複商品の確認
- 投稿履歴検索
- 投稿履歴CSV出力
- JSONバックアップ、復元
- スマートフォン対応
- お気に入り管理
- 投稿予定日の管理
- 月別投稿予定画面
- ジャンル別投稿数の表示
- ChatGPT用プロンプトをコピーする補助機能
- ROOM URL登録後、CodexがX・Threads文章を作成してアプリへ直接反映する機能
- ランキング・商品検索（通常ランキング／お得商品検索）

- 1位のみ、または1〜3位の取得順位選択
- カテゴリー別のランキング表示
- ランキング商品へのカテゴリーID、カテゴリー名、順位、取得日時の付加

## 使い方

1. `index.html` をブラウザで開きます。
2. 「設定」で楽天アプリIDと楽天アクセスキーを入力します。
3. 「商品検索」でキーワードを入力して検索します。
4. 商品カードからROOM投稿候補へ保存します。
   - ROOMへ投稿する商品は、このボタンを使います。
   - ROOMへ投稿せずThreadsだけで紹介する商品は「Threads投稿」を押します。候補管理画面の「Threads投稿」タブへ保存され、ROOM投稿待ちにならず、ROOM個別URLも要求しません。
5. 「投稿候補」では初期状態が「未投稿」です。「確認待ち」「すべて」へ切り替えられ、詳細は各候補カード内から開きます。
6. 紹介文が未作成なら、保存済みの商品情報と既存の生成機能で作成・保存します。保存済み文面は不要に再生成しません。
7. 今回の依頼でROOMへの実投稿を明示した場合だけ、候補画面の折りたたみ「Codex連携」に件数を含む指示を入力し、MacではCommand＋Enterで受け付けます。アプリは登録日時の古い順に候補ID・itemCodeを固定し、指定件数でキューを止めます。
8. 通常投稿は商品照合、文章・タグ入力、再確認を経てCodexがROOMの「完了」まで操作し、投稿成功と履歴保存を確認してから次候補へ進みます。投稿結果不明、商品不一致、重複警告などでは安全停止します。オリジナル写真投稿では写真操作・「完了」を行わず、人間操作待ちで停止します。
9. X・Threadsへの投稿はこのROOMキューでは行いません。SNS投稿の文章作成・公開は別途人が確認します。

Threads限定候補は「Threads限定投稿」欄で管理します。基本はThreads成果型 Ver.1を使い、確認済みの商品情報だけで文章を作成します。画面は「Threads生成文章｜親投稿」と「Threads生成文章｜コメント欄」の2段表示で、コピー操作も分離しています。設定画面に楽天アフィリエイトIDを入力した場合は、楽天APIが返すaffiliateUrlを保存して本文または返信用文章へ利用できます。楽天公式で人間が作成した`https://a.r10.to/...`形式の短縮URLは手動登録でき、登録済みの場合はそれを優先し、未登録ならaffiliateUrlへ戻します。短縮URLは自動生成せず、外部短縮サービスも使用しません。未設定・未取得時は商品URLやROOM URLを代用せず、URLを生成しません。外部Threadsへの投稿は自動化せず、親投稿を確認して投稿後にコメント欄の文章を投稿します。

Threads成果型 Ver.1では、誰向けを商品カテゴリー名だけで済ませず、商品情報から合理的に導ける具体的な利用場面・小さな困りごとへ絞ります。本文＋返信URL方式では、親投稿にURLを入れず、「対象は返信に👇」などの導線を置き、返信へ優先されたアフィリエイトURLと`#PR`を記載します。

親投稿は「具体的な誰向け→確認済みのお得情報→確認済み期限（ある場合）→返信への導線→#PR」の順で短く作成します。割引率・期限が確認済みの場合は曖昧な確認用文言を使わず、確認済みの事実を自然な文章にします。未確認の場合は割引率や期限の文章を省略し、推測で補いません。コメント欄は確認済み割引率があればその導線、選択中のaffiliateShortUrlまたはaffiliateUrl、`#PR`を含めます。

「ランキング・商品検索」が商品探索の入口です。通常ランキングは楽天ランキングAPI、トレンド検索とお得商品検索は楽天市場商品検索APIを使います。トレンド商品は1キーワードあたり5・10・20件、およびランキングは開始順位と5・10・20件を指定して探せます。ランキングが31位をまたぐ場合は必要なpageだけ取得し、楽天APIの正式rankで範囲を抽出します。商品カードから「ROOM投稿候補に保存」または「Threads投稿」を選びます。候補管理画面では、「投稿候補」タブがROOM投稿専用、「Threads投稿」タブがThreads限定アフィリエイト投稿専用です。タブを切り替えても保存データや投稿状態は変更されません。

「ランキング・商品検索」の「お得商品」では、カテゴリーを「すべて」または1カテゴリーに絞り、50%以上・50%・40%・30%・20%・10%の検索候補を楽天市場商品検索APIから探せます。検索ヒットは割引確認済みを意味しないため、確認した割引率・期限を入力して保存します。標準方式はThreads本文と`THREADS_REPLY`の分離で、親投稿にURLを入れず、確認済みの楽天アフィリエイトURLを返信用文章へ反映します。RaCouponは公式ページを開いて人間が確認する補助として扱い、直接スクレイピングは行いません。

楽天アプリIDまたは楽天アクセスキーを入れていない場合は、サンプル商品で動作確認できます。

## 楽天アプリIDについて

楽天APIの利用には、楽天ウェブサービスで発行されるApplication IDとAccess Keyの両方が必要です。

このアプリでは、両方をアプリの設定画面から入力します。

GitHubのHTMLやJavaScriptへApplication IDやAccess Keyを直接書かないでください。

この静的Webアプリでは、入力したApplication IDとAccess Keyをブラウザの `localStorage` に保存します。

GitHub Pagesなどの公開ページで使う場合、ブラウザの開発者ツールから保存内容を確認できる可能性があります。

より安全に運用する場合は、Netlify Functions、Cloudflare Workers、Vercel Functionsなどのサーバー側処理を利用し、Application IDとAccess Keyをサーバー側の環境変数で管理してください。

## 楽天ウェブサービスの利用について

このアプリは、楽天ウェブサービスの楽天市場商品検索APIを利用します。

また、ランキング画面では楽天ランキングAPIを利用します。

楽天ウェブサービス公式ルールに基づき、アプリ画面の最下部に公式クレジットバッジを表示しています。

このクレジット表示は削除しないでください。

クレジット表示を変更する場合は、必ず楽天公式のクレジット表示ガイドを確認してください。

公式確認先: https://webservice.rakuten.co.jp/guide/credit

楽天アプリIDと楽天アクセスキーは、GitHubのソースコードへ直接書かないでください。

アプリIDとアクセスキーは、利用者自身がアプリの設定画面から入力する仕様です。

このページには、検索エンジン向けに `noindex` 設定を入れています。ただし、検索エンジン側の反映には時間がかかる場合があります。

## 保存データ

データは同じブラウザ内の `localStorage` に保存されます。

保存対象は次のとおりです。

- 投稿候補
- 投稿履歴
- 紹介文
- ハッシュタグ
- アプリ設定

別の端末やブラウザには自動同期されません。

必要に応じて「設定」画面からJSONバックアップを保存してください。

## 注意

- 楽天会員IDやパスワードは保存しません。
- 楽天ROOMへのログイン情報は取得しません。
- アプリ自体はROOM投稿APIを呼びません。ROOM投稿が今回明示的に依頼された場合、Codexが通常のブラウザーUIを操作して投稿を完了できます。自動いいね、フォロー、コメントは行いません。
- 商品価格、在庫、セール期間は投稿前に楽天市場で確認してください。
- セール情報は商品データに明記された項目だけがプロンプトへ渡されます。記載がない割引率や通常価格を推測しません。
- 紹介文プロンプトは、商品情報から合理的に判断できる対象者や小さな悩みを冒頭へ置きます。状態不明の商品は使用体験を書かない指示になります。
- 商品信頼性チェックは自動断定ではありません。レビュー評価だけで安全判定せず、メーカー、型番、スペック、価格、保証、説明の整合性を確認し、判断できない場合は「要確認」とします。
- 注意喚起候補は、購入前に確認したい商品を整理するコレクション候補です。偽物・危険商品の断定やROOM側への自動登録は行いません。最終的なコレクション選択と投稿は利用者が確認して行います。
- 実際に使っていない商品を「使いました」と書かないでください。
- 医療、健康、美容などの効果を断定しないでください。
- 商品提供や専用クーポンなどがある場合は、PR表記の要否を利用者自身で確認してください。

   - `index.html`
   - `style.css`
   - `script.js`

4. 既存のPages公開方式・ブランチ・フォルダを確認し、今回の更新で設定を変更しないでください。

## Ver.2-7.1.3の投稿キューとCodex連携

投稿候補画面は、未投稿・確認待ち・すべてのフィルター、コンパクトカード、候補ごとの詳細を備えています。投稿済み候補は保存したまま通常一覧から隠します。

- Codex連携は通常折りたたまれています。今回の明示的な実投稿指示を入力し、MacではCommand＋Enterでキューを開始します。隠しボタン、localStorageの直接編集、商品コードからのROOM URL推測は使いません。
- 候補は`savedAt`の古い順で選び、candidate IDとitemCodeを固定します。画面フィルターや表示順でキュー対象を変えず、指定件数を超えません。
- 投稿前は投稿履歴・ROOM状態・商品情報を照合します。同一itemCodeの履歴、投稿済み、結果確認待ち、処理中の商品は再投稿しません。
- ROOMの「完了」は、今回の依頼で外部公開が明示され、商品と文面を照合できた通常投稿に限り操作します。入力後はsingle-post Skillに定める60秒を1回だけ待って再確認します。
- 投稿成功とアプリ履歴・キュー保存を確認した後だけ次候補へ進みます。結果不明では現在のキューを停止し、自動再投稿しません。ROOM重複警告は成功数へ含めず、記録・画面終了確認後だけ次へ進みます。
- オリジナル写真投稿では写真追加・編集と「完了」を行わず、人間操作待ちで停止します。
- 既存データ内の旧`pendingRoomPost`は現在の処理に使いません。既存候補・履歴・設定は自動初期化・削除・一括移行しません。

ROOM投稿後のSNS運用では、保存済みのROOM紹介文・ハッシュタグは再生成せず、確定したROOM個別URLを使ってX・Threadsだけを生成します。XはROOM URL・`#PR`・改行を含む全文140文字以内、Threadsには140文字制限を設けません。

通常運用では、SNSにも投稿する商品のROOM個別URLを「登録完了」した後、Codexが停止せずにX・Threads文章の作成・アプリ反映まで続けます。`===X_POST===` / `===THREADS_POST===`形式の結果をアプリへ直接反映し、検証後に人間の最終確認で停止します。ROOMだけに投稿する商品ではURL登録もSNS文章作成も行いません。アプリは外部AI APIへ接続しません。既存の「CodexでX・Threads作成」ボタンとChatGPT用プロンプトコピー機能は、補助・再実行・個別確認用です。
